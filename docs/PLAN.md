### 阶段 1 已完成任务记录

- 数据审计和文件级划分：`python train/audit_data.py`
- 生成 60 秒、步长 10 秒窗口：
  `python train/skab_dataset.py --window-size 60 --stride 10`
- 训练集 25 个文件、3,631 个窗口；验证集 5 个文件、542 个窗口；
  测试集 5 个文件、481 个窗口。
- 原始数据存在少量 2 秒采样抖动和更长采集停顿。窗口构建允许补齐 1 个缺失
  采样，间隔超过 2 秒时强制切段，禁止跨停顿形成窗口。
- 轻量 1D-CNN 训练完成，参数量 8,609；验证集选择阈值为 0.617513，
  测试集 Precision 0.969466、Recall 0.717514、F1 0.824675、
  ROC-AUC 0.921666。
- ONNX 导出使用 opset 13 和固定输入 `[1, 60, 8]`。32 个测试窗口的
  PyTorch/ONNX Runtime 最大绝对误差为 `8.58306884765625e-06`，满足
  `< 1e-4` 的验收标准。

### 阶段 2 已完成任务记录

- 没有只验证玩具 CNN，而是直接使用实际异常检测模型完成 ONNX -> ncnn
  转换，验证强度更高。
- ncnn `onnx2ncnn` 转换成功，生成 13 层 ncnn 模型；`ncnnoptimize`
  融合 Conv+ReLU 后得到 9 层模型。
- 使用 C++ ncnn 对 32 个真实测试窗口推理，与 ONNX Runtime 最大绝对误差
  为 `2.86102294921875e-06`。
- 发现并修复 `AdaptiveAvgPool1d` 在 ncnn 中的语义偏差。模型改为与固定
  60 秒输入等价的 15 点平均池化，不改变已训练权重。
- ncnn INT8 工具不支持 `Convolution1D`，模型改为数学等价的 `1×K`
  二维卷积并重新训练，参数量仍为 8,609。
- 使用 512 个训练集正常窗口完成 KL 校准，INT8 模型成功生成。
- 在 481 个测试窗口上，FP32 与 INT8 分类决策完全一致；
  Precision 0.970149、Recall 0.734463、F1 0.836013、F1 无下降。
- FP32 ncnn 权重文件 34,004 字节，INT8 权重文件 9,320 字节，
  权重部分减少约 72.6%；param 与 bin 合计从 35,313 字节降至
  10,645 字节，合计减少约 69.9%。

### 阶段 3-5 已完成任务记录

- 阶段 3 的 ARM64 `libncnn.a` 使用 GCC 13.3 交叉编译，关闭 Vulkan；
  `readelf`/`file` 确认静态库和测试可执行文件为 aarch64，且在
  QEMU 8.2.2 用户态下加载 INT8 模型并完成 481 个窗口推理。
- 阶段 4 的 `AnomalyDetector` 已封装模型加载、标准化、ncnn 推理、
  Sigmoid 和阈值判断。x86_64 与 QEMU ARM64 均通过集成测试，非法窗口
  长度会被拒绝，FP32 与 INT8 分类决策一致率均为 1.0。
- 阶段 5 新增 `anomaly_detector_benchmark.cpp` 和
  `scripts/benchmark_stage5.ps1`。计时范围覆盖预处理、输入写入、
  ncnn 推理和 Sigmoid，不含模型加载和文件 I/O。
- 每个 native/模型与 QEMU/模型组合重复 5 轮，延迟取 5 轮中位数；
  native 每轮预热 100 次、计时 2,000 次，QEMU 每轮预热 30 次、
  计时 1,000 次。P95 为每轮内按 nearest-rank 计算后取 5 轮中位数。
- 实测 x86_64 FP32 平均 `0.058912 ms`、P95 `0.082400 ms`；
  INT8 平均 `0.072774 ms`、P95 `0.097700 ms`。INT8 在该环境和小模型上
  平均延迟增加约 23.5%，没有观察到速度收益。
- 实测 QEMU ARM64 模拟环境 FP32 平均 `6.258285 ms`、P95
  `8.325100 ms`；INT8 平均 `4.386066 ms`、P95 `6.478800 ms`。
  这些是模拟数据，不能代表任何真实 ARM64 硬件的性能。
- 阶段 5 本轮实际耗时约 20 分钟，包含基准程序、5 轮重复测量和文档整理。
  阶段 3、4 的原实施耗时未留存，不补写估计值。

踩坑记录：

- CMake 的 OpenMP imported target 指向 `libgomp.so`，即使增加 `-static`
  仍会尝试静态链接动态库。交付构建改为显式链接工具链内的 `libgomp.a`。
- Windows 挂载目录不保留 Linux 权限，直接 `tar` 会把文件记录为 `777`。
  新增标准库 Python 归档器，显式写入目录、程序和普通文件的权限。
- glibc 对静态 `libgomp` 中的可选加速器 `dlopen` 路径给出链接警告；
  当前仅使用 CPU OpenMP，已通过 QEMU 验收。真机仍作为阶段 6B 的首要检查项。

踩坑记录：

- 板端脚本必须记录运行时的 CPU 调频策略、前后温度和接口信息，否则不同散热
  或降频状态下的延迟数字不可解释。
- 首次烧录完成后出现主 GPT CRC 错误，U-Boot 只能回退到备用 GPT，Linux
  未能完成启动。源镜像校验正常；使用 USBImager 物理磁盘模式重写并启用
  Verify 后 GPT 错误消失，确认是烧录问题。
- 默认 `ondemand` 策略试跑的 P95 在各轮间波动明显；正式基线临时切换到
  `performance`，测后恢复 `ondemand`，并在结果中同时保留试跑数据。
- QEMU 回归必须使用显式短参数，并保留 `qemu-aarch64` 记录，避免模拟结果与
  真机结果混写。
